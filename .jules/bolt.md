## 2024-05-18 - Avoid Generalized List Comprehensions in Tic-Tac-Toe Minimax Heuristics
**Learning:** For static grid evaluations (like 3x3 Tic-Tac-Toe) in highly recursive algorithms, generating lines dynamically using list comprehensions (`[[board[r][c] for r in range(3)] for c in range(3)]`) in leaf-node heuristics results in massive object allocation overhead and slows down search trees. Profiling showed `winner` taking >50% of runtime due to list allocations in `Min Max.py`.
**Action:** Replace dynamic line generation and generalized `all()` checks with hardcoded array index comparisons. A simple O(1) manual comparison per line (`board[0][0] == board[1][1] == board[2][2]`) provides a ~3.7x speedup for the full Minimax pass.
## 2024-05-18 - Branch and Bound Pruning in Traveling Salesman Problem (TSP)
**Learning:** For permutation-based searches like TSP, calculating the cost of full paths inside the loop generates unnecessary overhead for paths that are already suboptimal. Building list copies (`[start] + list(perm) + [start]`) for every iteration also creates unnecessary allocations.
**Action:** Implement early branch and bound pruning: break the loop early if the current partial cost equals or exceeds the known minimum cost (dynamically verify edge weights are non-negative first for safety). Also defer path list construction until a new minimum is found. Finally, handle edge cases for 1-node graphs before permutation generation to prevent empty iterator IndexErrors.
