## 2024-05-18 - Avoid Generalized List Comprehensions in Tic-Tac-Toe Minimax Heuristics
**Learning:** For static grid evaluations (like 3x3 Tic-Tac-Toe) in highly recursive algorithms, generating lines dynamically using list comprehensions (`[[board[r][c] for r in range(3)] for c in range(3)]`) in leaf-node heuristics results in massive object allocation overhead and slows down search trees. Profiling showed `winner` taking >50% of runtime due to list allocations in `Min Max.py`.
**Action:** Replace dynamic line generation and generalized `all()` checks with hardcoded array index comparisons. A simple O(1) manual comparison per line (`board[0][0] == board[1][1] == board[2][2]`) provides a ~3.7x speedup for the full Minimax pass.

## 2024-05-18 - Eliminating Generator Allocation Overhead in Recursive Tree Searches
**Learning:** In highly recursive searches like Minimax and Alpha-Beta, generating full array copies of states for every possible move creates enormous object allocation overhead and garbage collection pressure. Profiling showed that dynamic state cloning (`[row[:] for row in board]`) in `get_children` and list comprehensions / generators (like `all(...)`) in evaluation heuristics dominate runtime.
**Action:** Replace `deepcopy` and full state cloning with in-place backtracking (mutating the board temporarily, recursively calling the function, and restoring the state). Additionally, unroll dynamic list manipulations (like generators or `zip`) into explicit index-based assignments and `in` keyword checks for presence testing, which are implemented natively in C and avoid Python object creation overhead. This yields a massive performance multiplier (~7-8x speedup) for recursive AI algorithms.
