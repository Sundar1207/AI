## 2024-05-18 - Avoid Generalized List Comprehensions in Tic-Tac-Toe Minimax Heuristics
**Learning:** For static grid evaluations (like 3x3 Tic-Tac-Toe) in highly recursive algorithms, generating lines dynamically using list comprehensions (`[[board[r][c] for r in range(3)] for c in range(3)]`) in leaf-node heuristics results in massive object allocation overhead and slows down search trees. Profiling showed `winner` taking >50% of runtime due to list allocations in `Min Max.py`.
**Action:** Replace dynamic line generation and generalized `all()` checks with hardcoded array index comparisons. A simple O(1) manual comparison per line (`board[0][0] == board[1][1] == board[2][2]`) provides a ~3.7x speedup for the full Minimax pass.

## 2024-05-18 - Minimize Object Cloning in Recursive Tree Searches
**Learning:** In highly recursive algorithms like Minimax and Alpha-Beta, creating full copies of state arrays (e.g., `[row[:] for row in board]`) at every branch node generates extreme object allocation overhead and garbage collection pressure, massively slowing down search trees. Profiling showed this overhead dominated runtime alongside dynamic array generations in leaf heuristics.
**Action:** Use in-place state modification (backtracking) within the recursive loops to safely traverse paths without creating copies. By combining this with manual O(1) index comparisons instead of list comprehensions, runtime for `Alpha Beta.py` was reduced from ~0.61s to ~0.05s.
