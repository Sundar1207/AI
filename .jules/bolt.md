## 2024-05-18 - Avoid Generalized List Comprehensions in Tic-Tac-Toe Minimax Heuristics
**Learning:** For static grid evaluations (like 3x3 Tic-Tac-Toe) in highly recursive algorithms, generating lines dynamically using list comprehensions (`[[board[r][c] for r in range(3)] for c in range(3)]`) in leaf-node heuristics results in massive object allocation overhead and slows down search trees. Profiling showed `winner` taking >50% of runtime due to list allocations in `Min Max.py`.
**Action:** Replace dynamic line generation and generalized `all()` checks with hardcoded array index comparisons. A simple O(1) manual comparison per line (`board[0][0] == board[1][1] == board[2][2]`) provides a ~3.7x speedup for the full Minimax pass.

## 2024-05-18 - Eliminate Object Allocation Overhead with In-Place Backtracking in Game Trees
**Learning:** In highly recursive game tree search algorithms like Alpha-Beta pruning, creating deep copies or new array objects for every child node (e.g. `[row[:] for row in board]`) inside the expansion loop generates severe object allocation overhead and GC pressure. Profiling `Alpha Beta.py` showed a high number of list append/extend operations slowing down tree traversal.
**Action:** Replace `get_children()` allocation strategies with in-place board state modification (backtracking). Apply the move directly to the current board (`position[i][j] = 'X'`), recurse, and then revert the state (`position[i][j] = ' '`). This eliminated `O(b^d)` list allocations and sped up the evaluation from ~1.02s to ~0.10s.
