## 2024-05-18 - Avoid Generalized List Comprehensions in Tic-Tac-Toe Minimax Heuristics
**Learning:** For static grid evaluations (like 3x3 Tic-Tac-Toe) in highly recursive algorithms, generating lines dynamically using list comprehensions (`[[board[r][c] for r in range(3)] for c in range(3)]`) in leaf-node heuristics results in massive object allocation overhead and slows down search trees. Profiling showed `winner` taking >50% of runtime due to list allocations in `Min Max.py`.
**Action:** Replace dynamic line generation and generalized `all()` checks with hardcoded array index comparisons. A simple O(1) manual comparison per line (`board[0][0] == board[1][1] == board[2][2]`) provides a ~3.7x speedup for the full Minimax pass.

## 2024-05-18 - Early Pruning and Object Allocation Reduction in Iterative Algorithms
**Learning:** For brute-force iteration (like permutation generation in TSP), continuously generating full objects (`[start] + list(perm) + [start]`) inside the evaluation loop introduces significant allocation overhead in Python. Furthermore, if the loop does not include an early termination condition (branch and bound), it needlessly evaluates paths that are mathematically guaranteed to be sub-optimal.
**Action:** When working with brute-force permutations, delay the instantiation of complete state arrays until after confirming they constitute a new optimum. Secondly, use a `can_prune` check (e.g., verifying there are no negative weights in pathfinding) to allow for early break conditions (`if current_cost >= min_cost: continue`) at each step of the inner evaluation loop.
