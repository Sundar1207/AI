## 2024-05-18 - Avoid Generalized List Comprehensions in Tic-Tac-Toe Minimax Heuristics
**Learning:** For static grid evaluations (like 3x3 Tic-Tac-Toe) in highly recursive algorithms, generating lines dynamically using list comprehensions (`[[board[r][c] for r in range(3)] for c in range(3)]`) in leaf-node heuristics results in massive object allocation overhead and slows down search trees. Profiling showed `winner` taking >50% of runtime due to list allocations in `Min Max.py`.
**Action:** Replace dynamic line generation and generalized `all()` checks with hardcoded array index comparisons. A simple O(1) manual comparison per line (`board[0][0] == board[1][1] == board[2][2]`) provides a ~3.7x speedup for the full Minimax pass.
## 2024-05-18 - Use Backtracking and Early Returns in Minimax with Alpha-Beta Pruning
**Learning:** In highly recursive tree searches (like Minimax and Alpha-Beta), avoiding the creation of full copies of state arrays (e.g., `[row[:] for row in board]`) for each child state significantly reduces execution time by eliminating object allocation overhead and garbage collection pressure. Replacing `get_children` with in-place state modification (backtracking) within the recursive loop and using an early return (e.g., `return max_eval`) when the cutoff condition (`beta <= alpha`) is met successfully breaks out of nested loops immediately, providing a 6x speedup.
**Action:** Replace `get_children` implementations in minimax/alpha-beta searches with an in-place state modification, recursive call, and state reversion (backtracking). Use early returns on pruning condition to break out of nested grid search loops immediately.
## 2024-05-18 - Inline Game Evaluation Logic in Minimax Algorithms
**Learning:** Functions like `game_over` and `evaluate` in recursive search algorithms (like Minimax/Alpha-Beta) introduce function call overhead and redundant checks when they call a core evaluation function like `winner` repeatedly. Inlining the evaluation logic directly into the recursive function and eliminating wrapper functions reduces function calls by over 50%. Combined with backtracking and using `in` for empty space checks, runtime decreased significantly.
**Action:** Inline `winner` logic directly into `game_over` or `evaluate`, or inline `winner` directly into the minimax function. Use simple inline checks like `if ' ' in board[0] or ' ' in board[1] or ' ' in board[2]` instead of full array iteration to check for draws. Replace `max()` and `min()` with simple `if eval > max_eval` checks inside hot loops to save function call overhead.
