## 2024-05-18 - Avoid Generalized List Comprehensions in Tic-Tac-Toe Minimax Heuristics
**Learning:** For static grid evaluations (like 3x3 Tic-Tac-Toe) in highly recursive algorithms, generating lines dynamically using list comprehensions (`[[board[r][c] for r in range(3)] for c in range(3)]`) in leaf-node heuristics results in massive object allocation overhead and slows down search trees. Profiling showed `winner` taking >50% of runtime due to list allocations in `Min Max.py`.
**Action:** Replace dynamic line generation and generalized `all()` checks with hardcoded array index comparisons. A simple O(1) manual comparison per line (`board[0][0] == board[1][1] == board[2][2]`) provides a ~3.7x speedup for the full Minimax pass.
## 2024-05-19 - Fast Path Evaluation in Traveling Salesman Problem
**Learning:** In combinatorial search algorithms like TSP, evaluating paths by generating full lists and iterating over them `current_path = [start] + list(perm) + [start]` for each permutation causes massive overhead from list allocation and iteration. Using early branch-and-bound pruning is effective, but it only works safely if edge weights are non-negative.
**Action:** Calculate the path cost directly on the permutation iterator and apply early pruning to exit the loop immediately if the cost exceeds the best-known minimum. Defer explicit path list construction until a new minimum is actually found. This provides a ~2.5x speedup. Always check edge weights dynamically to preserve support for graphs with negative weights.
